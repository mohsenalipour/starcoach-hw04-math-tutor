# تمرین چهارم — Complex Mathematics Tutor

مدرس ریاضی مایلو، با **LangGraph**، State مشخص، نودهای مستقل و ارتباط از طریق CLI. کاربر می‌تواند مفهوم ریاضی بپرسد، مسئله حل کند، سطح توضیح را تغییر دهد و اجرای گراف را ببیند.

گراف مرجع بخش ریاضی در [ریپوی تمرین سوم](https://github.com/mohsenalipour/starcoach-hw03-agent-architecture) و [ARCHITECTURE.md](ARCHITECTURE.md) مشخص شده و همان گراف در `agent.py` پیاده‌سازی شده است. فایل `graph.mmd` از خود گراف اجراشونده تولید می‌شود.

برای ارائه، [راهنمای دمو](DEMO.md) ترتیب دقیق سؤال‌ها و فرمان‌ها را دارد. [معماری](ARCHITECTURE.md) Graph و State را توضیح می‌دهد و [شواهد بررسی](TESTING.md) نتیجهٔ تست‌ها را ثبت می‌کند.

## اجرای سریع

اگر محیط پروژه و `.env` آماده‌اند، در ترمینال VS Code و از داخل پوشهٔ پروژه فقط این دستور را اجرا کنید:

```powershell
.\.venv\Scripts\python.exe cli.py
```

برنامه **بدون آرگومان** وارد گفت‌وگو می‌شود. وقتی `You>` ظاهر شد، سؤال را بنویسید و Enter بزنید؛ پاسخ با عنوان `Milo>` در همان ترمینال نمایش داده می‌شود. سطح و زبان ابتدا `auto` هستند و از سؤال و زمینه تشخیص داده می‌شوند. برای شروع یک توضیح ساده، سطح نامشخص به مبتدی تبدیل می‌شود.

روی سیستم تازه، پروژه را دریافت و نصب کنید:

```powershell
git clone https://github.com/mohsenalipour/starcoach-hw04-math-tutor.git
cd starcoach-hw04-math-tutor
.\setup.ps1
notepad .env
```

در `.env` کلید و مدل را تنظیم و فایل را ذخیره کنید، سپس همان دستور اجرای بدون آرگومان را بزنید. فعال‌سازی دستی محیط مجازی لازم نیست. `setup.ps1` فایل `.env` را فقط در صورت نبودن از نمونه می‌سازد و تنظیمات موجود را جایگزین نمی‌کند.

مثال گفت‌وگو؛ هر سؤال را پس از دریافت پاسخ قبلی وارد کنید:

```text
You> I don't know calculus. Explain derivatives using an everyday example.
You> Differentiate x^3 + 2*x step by step.
You> /trace
You> /state
You> /exit
```

فایل کمکی زیر نیز همان برنامه را بدون آرگومان اجرا می‌کند:

```powershell
.\run.ps1
```

اگر اجرای اسکریپت PowerShell محدود باشد، از دستور مستقیم Python در ابتدای راهنما استفاده کنید.

## نمایش رنگی در CLI

رنگ‌ها در ترمینال سازگار به‌صورت خودکار فعال‌اند و به بستهٔ اضافی یا آرگومان نیاز ندارند:

| بخش | نمایش |
|---|---|
| سؤال و شمارهٔ مراحل | آبی فیروزه‌ای |
| پاسخ آموزشی | سبز |
| عنوان مایلو و نودهای در حال اجرا | بنفش |
| عنوان مثال، پرسش یادگیری و عبارت‌های برجسته | زرد |
| جواب نهایی | سبز، پررنگ و زیرخط‌دار |
| خطا | قرمز |
| متن راهنمای کوتاه و جداکننده | خاکستری |

`terminal.py` فقط نمایش را قالب‌بندی می‌کند؛ State، تاریخچه، JSON و گزارش HTML متن اصلی را نگه می‌دارند. توان‌هایی مانند `x**2` به‌عنوان تأکید Markdown تفسیر نمی‌شوند. رنگ در خروجی هدایت‌شده به فایل یا pipe، با وجود متغیر `NO_COLOR` یا با `TERM=dumb` خاموش می‌شود. رنگ‌بندی، مشکل راست‌به‌چپ ترمینال را حل نمی‌کند؛ روش فارسی در [راهنمای دمو](DEMO.md#فارسی-و-فایل-ورودی) آمده است.

## نصب روی سیستم دیگر

Python 3.10 یا جدیدتر لازم است؛ روی Python 3.14 تست شده است.

```powershell
.\setup.ps1
```

سپس در `.env` مقدار `OPENAI_API_KEY`، `OPENAI_MODEL` و در صورت نیاز `OPENAI_BASE_URL` را تنظیم کنید. مثال اولیه برای AvalAI است. برای OpenAI مستقیم، مقدار `OPENAI_BASE_URL` را خالی بگذارید. برای Metis نیز سه متغیر `METIS_API_KEY`، `METIS_BASE_URL` و `METIS_CHAT_MODEL` پشتیبانی می‌شود؛ وجود کلید Metis آن را فعال می‌کند.

نصب دستی و اجرای مستقل از PowerShell:

```text
python -m venv .venv
# Windows:
.venv\Scripts\python.exe -m pip install -r requirements.txt
# Linux/macOS:
.venv/bin/python -m pip install -r requirements.txt
```

کپی `.env.example` به `.env` و تنظیم کلید برای نصب دستی لازم است. فایل تنظیمات به‌طور پیش‌فرض کنار `cli.py` خوانده می‌شود؛ متغیرهای محیطی موجود اولویت دارند. با `--env-file` می‌توان فایل دیگری را انتخاب کرد.

## امکانات اختیاری هنگام اجرا

برای استفادهٔ روزمره و دمو، اجرای بدون آرگومان کافی است. گزینه‌های زیر برای اجرای تک‌سؤال، استخراج داده یا ابزارهای جانبی هستند:

```powershell
.\.venv\Scripts\python.exe cli.py -q 'Differentiate x^3 + 2*x step by step.' --trace
.\.venv\Scripts\python.exe cli.py -q 'Solve 2*x + 3 = 7 step by step.' --json --state-file .\demo\output\session.json
.\.venv\Scripts\python.exe cli.py --graph
.\.venv\Scripts\python.exe cli.py --help
```

`--trace` نام نودها را هنگام اجرا و مسیر نهایی را در stderr نمایش می‌دهد. `--json` خروجی کامل State را در stdout می‌نویسد و برای حالت تک‌سؤال است. `--graph` بدون اتصال به مدل یا کلید API کار می‌کند.

`--input-file` سؤال را از فایل UTF-8 با یا بدون BOM می‌خواند. `--html` گزارش خوانای راست‌به‌چپ یا چپ‌به‌راست از آخرین پاسخ، مسیر و State ذخیره می‌کند. پوشهٔ خروجی باید موجود باشد؛ پوشهٔ `demo/output` آماده و خروجی‌هایش از Git خارج هستند. در گفت‌وگوی تعاملی، `--html` بعد از هر نوبت همان فایل را به‌روز می‌کند.

متن سؤال به صورت positional یا با `-q` و `--input-file` قابل دریافت است؛ برای یک اجرا یکی از این سه منبع را انتخاب کنید. `--level` و `--language` ترجیح اولیه را تعیین می‌کنند؛ همان ترجیح‌ها در گفت‌وگو با `/level` و `/language` قابل تغییرند. `--env-file` مسیر تنظیمات را انتخاب می‌کند و `--state-file` پس از هر نوبت، State آخرین نتیجه را ذخیره می‌کند.

## فرمان‌های گفت‌وگو

| فرمان | عملکرد |
|---|---|
| `/level auto` | تشخیص سطح از متن و سابقه؛ پیش‌فرض مبتدی |
| `/level beginner` | توضیح شهودی، تعریف نمادها و مثال روزمره |
| `/level intermediate` | روش حل و اتصال شهود به فرمول |
| `/level advanced` | تعریف دقیق، فرض‌ها و استدلال فنی |
| `/language auto`، `/language fa`، `/language en` | انتخاب زبان |
| `/trace` | مسیر نودهای آخرین سؤال و نوع بررسی پاسخ |
| `/trace on`، `/trace off` | نمایش یا خاموش کردن پیشرفت نودها |
| `/state` | State آخرین اجرا به شکل JSON |
| `/save demo/output/session.json` | ذخیرهٔ State آخرین اجرا در پوشهٔ خروجی محلی |
| `/file question.txt` | خواندن سؤال از فایل UTF-8 در همین گفت‌وگو |
| `/html report.html` | ذخیرهٔ آخرین نتیجه در گزارش HTML قابل نمایش در مرورگر |
| `/graph` | گراف واقعی برنامه به صورت Mermaid |
| `/new` | پاک کردن سابقه، سؤال معلق و آخرین State؛ حفظ تنظیم سطح، زبان و نمایش trace |
| `/help` | راهنما |
| `/exit` یا EOF | خروج |

`/level auto` تشخیص سطح را دوباره فعال می‌کند. `/trace on` نام نودها را هنگام شروع اجرا نشان می‌دهد و در پایان، مسیر و نوع بررسی پاسخ را چاپ می‌کند. `/trace` به‌تنهایی فقط اطلاعات آخرین نوبت را نمایش می‌دهد. `/state` پیش از اولین سؤال مقدار `null` دارد؛ `/save` و `/html` به یک نوبت کامل‌شده نیاز دارند.

در حالت `auto` پیام دارای حروف فارسی، یا ادامهٔ یک درخواست معلق فارسی، پاسخ فارسی می‌گیرد. برای توضیح فارسی دربارهٔ عبارتی مانند `x^2` می‌توان `/language fa` را انتخاب کرد. نمایش چیدمان راست‌به‌چپ به ترمینال وابسته است. سناریوی اصلی [DEMO.md](DEMO.md) همهٔ سؤال‌ها و پاسخ‌ها را در CLI نشان می‌دهد. فایل ورودی و گزارش HTML امکانات جانبی برای بررسی فارسی هستند؛ مرورگر فقط گزارش را نمایش می‌دهد.

## بررسی پاسخ و مدیریت خطا

برای همهٔ پاسخ‌ها، نود `review_answer` درستی، وضوح، ارتباط با سؤال و تناسب سطح را بررسی می‌کند. برای مسئله‌های قابل پشتیبانی، SymPy نیز محاسبه را مستقل انجام می‌دهد؛ نتیجهٔ اشتباه حتی با تأیید مدل به مسیر اصلاح می‌رود. نود اصلاح به‌طور پیش‌فرض فقط یک بار اجرا می‌شود. اگر پاسخ همچنان تأیید نشود، برنامه نتیجهٔ نامطمئن را به عنوان پاسخ نهایی منتشر نمی‌کند و درخواست دقیق‌تر شدن سؤال می‌دهد.

ابزار محلی مشتق، انتگرال با کران ثابت یا بدون کران، معادلهٔ چندجمله‌ای تک‌متغیره روی اعداد حقیقی، ساده‌سازی و دترمینان ماتریس عددی تا ۴×۴ را پشتیبانی می‌کند. حدود متغیر، معادلات پیچیده‌تر و مسائل خارج از این محدوده فقط با بازبینی مدل بررسی می‌شوند. وضعیت `symbolically_checked` یعنی نتیجهٔ نهایی با ابزار مقایسه شده؛ `reviewed_with_tool` یعنی محاسبه موجود است ولی تطبیق ماشینی عبارت نهایی ممکن نبوده؛ `model_reviewed` یعنی فقط مدل بازبینی کرده است. این بررسی‌ها اثبات عمومی درستی همهٔ پاسخ‌ها نیستند.

عبارت‌ها با AST محدود خوانده می‌شوند و `eval` یا پارس آزاد SymPy روی ورودی اجرا نمی‌شود. محاسبه در یک فرایند جدا با مهلت ۶ ثانیه انجام می‌شود. پاسخ هر نود مدل با Pydantic اعتبارسنجی می‌شود؛ پاسخ JSON نامعتبر حداکثر یک بار اصلاح می‌شود. قطع شبکه، کلید نامعتبر، محدودیت اعتبار و پایان مهلت درخواست پیام قابل‌فهم می‌دهند. در صورت خطای مدل، سابقهٔ گفت‌وگو دست‌نخورده باقی می‌ماند.

حافظه به ۱۲ پیام قبلی محدود است و در RAM نگه داشته می‌شود. ذخیرهٔ State فقط با فرمان یا گزینهٔ صریح انجام می‌شود؛ پس از بستن برنامه، گفت‌وگو خودکار بازیابی نمی‌شود. کلید API وارد State، trace یا فایل تحویل نمی‌شود. سؤال‌ها و بخشی از سابقه برای ارائه‌دهندهٔ مدل انتخاب‌شده ارسال می‌شوند.

## تست و تحویل

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

تست‌ها مسیر مفهومی و حل مسئله، شفاف‌سازی، اصلاح محدود، جلوگیری از تأیید جواب غلط، حافظهٔ چندنوبتی، ذخیرهٔ State، عملیات ریاضی، ورودی نامعتبر، خطاهای مدل و فرمان‌های CLI را بررسی می‌کنند. این تست‌ها به کلید API نیاز ندارند. شواهد اجرای واقعی در پوشهٔ `examples` قرار دارد.

۳۵ تست محلی پاس شده‌اند؛ جزئیات محیط و تفکیک تست شبیه‌سازی‌شده از اجرای واقعی در [TESTING.md](TESTING.md) است.

فایل ZIP تحویل، کد و مستندات را دارد. `.env`، محیط مجازی و cache در آن قرار نمی‌گیرند. برای تحویل کلید API را ارسال نکنید.

## تغییرات بعدی

برای تغییر رفتار Agent، `agent.py` و تست‌های مرتبط را بررسی کنید؛ برای رنگ و قالب‌بندی ترمینال، `terminal.py` را تغییر دهید. پس از تغییر Graph، `graph.mmd` و [معماری](ARCHITECTURE.md) را با خروجی `--graph` هماهنگ کنید و ارتباط آن با گراف تمرین سوم را بررسی کنید. ترتیب اصلی ارائه در [DEMO.md](DEMO.md) نگه داشته می‌شود.
